The TrustVault approach

Private storage. Explicit access. A record you can examine.

Three principles shape every request, from an upload to a refused edit.

01

Private by default

A document is visible to its owner and to the accounts the owner explicitly grants. Administrators do not receive implicit access to document contents.

02

Permissioned access

Owners choose Read or Edit for each person. The server checks the current grant on every request, so a revoked permission stops working on the next request.

03

Provable activity

Important operations are recorded in a hash-chained audit log. A change to recorded history breaks the chain and can be detected.

Features

Everything you need for controlled document work.

Only capabilities implemented in the application are described here.

No anonymous document access. The public preview is static. Your documents are never loaded for visitors who are not signed in.

  • Secure authentication

    Passwords are hashed with bcrypt. Sessions are server-side, HttpOnly, and re-checked against the account on every request.

  • Three enforced roles

    Admin, Document Owner, and Viewer permissions are evaluated by the API, not by the browser.

  • Server-side file validation

    PDF, JPEG, and PNG content is verified by magic bytes and capped at 5 MiB.

  • Search and filtering

    Find documents by name, description, owner, category, or created date — always inside your access.

  • Read and Edit grants

    Access is granted per document and per account, with no broad public links.

  • Sharing and revocation

    Owners can grant or revoke access; the next request uses the current permission state.

  • Account disabling

    Administrators can disable an account and invalidate its active sessions.

  • Audit events and verification

    Important operations enter a SHA-256 hash chain. Administrators can verify integrity from the Audit log.

How it works

Simple, secure, and transparent.

Three steps from a private file to a reviewable access history.

Step 01

Upload a document

A Document Owner adds a PDF, JPEG, or PNG. The server validates the content before it is stored.

Step 02

Grant specific access

Choose an account and a Read or Edit grant. Access stays scoped to that person and document.

Step 03

Review and verify

Follow important actions in the Audit log and verify the hash chain from the Admin console.

Integrity

A recorded history you can examine.

TrustVault writes important operations to a hash-chained audit log. Each entry includes a hash of the previous entry, so a change to recorded history breaks the chain and can be detected.

  • Uploads, grants, revocations, refusals, and account changes are recorded.
  • SHA-256 hash chain over audit events.
  • Administrators can verify the current chain from the Audit log.
  • Deleting a document does not rewrite older audit entries.

Tamper-evident, not tamper-proof. A database administrator with enough access could rewrite records and recompute hashes. The chain makes undetected changes harder, not impossible.

Architecture

A small, inspectable stack.

Built with the technologies already running TrustVault: the browser, the Express application, and PostgreSQL.

Client

Browser

Static HTML, CSS, and vanilla JavaScript. Same-origin calls to the application API.

Server

Express application

Authentication, authorization, document handling, and audit writing on Node.js.

Data

PostgreSQL

Users, sessions, documents, permissions, audit records, and document blobs, with a local write-through file cache.
